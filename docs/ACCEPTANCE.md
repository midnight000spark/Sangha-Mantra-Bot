# Приёмка maintenance PR #1

## Локально

Typecheck, 189 тестов (831 assertions), локальный workerd/D1, backup/restore drill и dry-run TEST build прошли. Изменённые регрессии проверяют новую семантику нескольких чисел, один notice на исходное сообщение, silent backlog и ограничения TEST bot intake. Существующие тесты покрывают конкурентные команды, четыре гонки перед/после последней проверки разрешения отправки, UNCERTAIN и старые редакции.

Gitleaks проверил рабочие файлы и публичную историю; отдельное сравнение с выданными тестовыми credentials не нашло совпадений в исходниках. Private config, токены, D1 evidence и receipts находятся вне checkout с ограниченными правами.

## Миграция и состояние базы

0007 применена к новой локальной копии доступного зашифрованного архива рабочей базы от 12 ноября 2026, 18:17 UTC. Все прежние столбцы 18 таблиц совпали до/после. Сообщения 32/38 присутствуют, их нулевые overrides и effective amounts сохранены. Миграция сама не задаёт границу учёта. Это проверка архивной копии, не текущей production-суммы или полноты последующих событий.

Production D1, бот, токен, webhook и deployment в этой работе не изменялись. Реальная production-граница не назначалась. Безопасная последовательность и совместимый rollback: [PRODUCTION_TRANSITION.md](PRODUCTION_TRANSITION.md).

## Границы доказательств

Повторные и устаревшие события проверяются захваченными после настоящей доставки envelopes через аутентифицированный webhook. Это fault injection, а не наблюдение повторной доставки со стороны Telegram. Записи вкладов или ожидаемых результатов напрямую в D1 не создаются: SQL-записи setup ограничены новой TEST identity, campaign, alias, marker boundary и исходной тишиной.

Локальные гонки/UNCERTAIN не выдаются за живую потерю ответа Telegram. Не подтверждены живым прогоном: обычный человек-отправитель и inline callbacks, длительная тишина через ежедневные отчёты и снятие их удержаний, текущие production-данные, CPU/квоты и внешнее восстановление рабочей системы. Наличие Cron heartbeat само по себе не подтверждает отправку ежедневного отчёта.

В ходе отладки исполнителя устранены: HTTP403 на стандартный Python User-Agent; разные private message IDs у двух ботов; чувствительное к регистру сопоставление русского ответа. Эти сбои не были ошибками учёта; частичные прогоны не объявлены полным PASS. Их данные не сбрасывались, последующий прогон использует фактический baseline.

## Настоящий Telegram и TEST D1 — PASS

Полный автономный прогон 13 ноября 2026 завершился успешно на отдельном TEST Worker/D1 с двумя выделенными ботами. Перед началом подтверждены getMe, закрытая test group, администраторские права и наблюдение настоящего ответа принимающего бота через getUpdates отправителя. Прогон повторно запущен на сохранённых данных после диагностических попыток; ручной ввод сообщений и сброс базы не потребовались.

Проверены:

- `1000`, `1000🙏`, `10 и 10`, `1000 2000`, `1.5`, `0`, `Привет` в обоих режимах. Суммы совпали; правильные значения приняты молча, неправильные получили по предупреждению только вне тишины. Silent notices остались PENDING с hold, без ответов в Telegram.
- Настоящие фото и видео с подписью `1000` не внесли вклад.
- Пять последовательных реальных редакций одного источника в каждом режиме, включая число → несколько чисел → число → текст → число; D1 каждый раз совпала с ожидаемой суммой. Захваченные duplicate/stale envelopes не изменили последний итог.
- `/silent`, on/off/status, повторный ON, `/status` и json, `/recent`, `/inspect` и json, `/reports`, `/notices`, `/help` через реальный private Bot-to-Bot административный путь. Текстовые ответы проверены; внутренние статусы в обычных recent/inspect отсутствуют.
- `/override`, последующая настоящая правка источника, сохранение приоритета override, `/release` к последнему значению источника и `/import` отдельного проверенного тестового сообщения.
- Повторный настоящий cloud deployment в режиме тишины сохранил состояние D1. После OFF ранее удержанные предупреждения не отправились. Финальное состояние — /silent on, health ok.

Итоговая прибавка полного прогона — 2 432 тестовые мантры относительно фактического baseline; это не production total. Наблюдался настоящий Cron heartbeat. Ежедневный отчёт за новый тестовый день ещё не наступил и не объявлен проверенным. Private receipt содержит версии deployment, перечень проверок и fingerprint src/migrations; fingerprint сверен с подготовленным кодом.

Вердикт: GO для независимого ревью изменений. NO-GO для немедленного production deploy: требуется отдельное разрешение, реальные guards/config, подтверждённая рабочая граница, свежая копия/сверка и выполнение плана перехода. PR остаётся открытым, merge и production deploy не выполняются.
